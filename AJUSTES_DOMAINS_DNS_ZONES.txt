RELATÓRIO DE AJUSTES — DOMÍNIOS E ZONAS DNS
Data: 20/06/2026

ARQUIVOS PRINCIPAIS
- domains.php
- dns-zones.php

1. NOMENCLATURA
- Padronização dos textos para “zona reversa IPv4” e “zona reversa IPv6”.
- Atualização dos títulos informativos das zonas reversas.

2. VALIDAÇÃO DO CADASTRO
- IPv4 e IPv6 passaram a ser validados de forma independente.
- Os erros são acumulados por campo, sem interromper no primeiro problema.
- Erros simultâneos destacam todas as seções correspondentes.
- Nenhuma alteração DNS é aplicada quando existe erro bloqueante.
- A reutilização de prefixo IPv6 continua bloqueada.
- A rolagem após erro respeita a ordem do formulário.

3. UX DO FORMULÁRIO
- Ao editar uma rede IPv4 com erro, o destaque e a mensagem dessa seção são removidos.
- Ao editar um prefixo IPv6 com erro, apenas o erro dessa seção é removido.
- Os demais erros permanecem visíveis.
- O PHP volta a validar normalmente no próximo envio.

4. BOTÃO “GERAR EXEMPLO”
- Adicionado preenchimento com dados reservados para documentação:
  Domínio: exemplo.com.br
  IPv4 NS1: 192.0.2.253
  IPv4 NS2: 192.0.2.254
  IPv6 NS1: 2001:db8:2000::242
  IPv6 NS2: 2001:db8:2000::243
  Rede IPv4: 192.0.2.0/24
  Prefixo IPv6: 2001:db8::/32
- Os campos PTR não são preenchidos automaticamente.
- Foi incluída uma explicação sobre a finalidade do botão.
- A página sobe ao topo após preencher os exemplos.
- Os valores gerados são limpos após quatro segundos.
- Valores alterados manualmente pelo usuário durante esse período são preservados.

5. TEXTOS INFORMATIVOS
- Ajustado o texto sobre prefixos IPv4 entre /16 e /24.
- Removido o exemplo baseado em rede privada 192.168.x.x.
- Novo texto explica que uma rede /22 é dividida em quatro blocos /24.

6. FLUXO PÓS-CRIAÇÃO
- Após criação real do domínio, é exibido um card central de sucesso.
- O card informa que o usuário será redirecionado.
- O redirecionamento para dashboard.php ocorre após aproximadamente três segundos.
- Erros e validações bloqueadas não provocam redirecionamento.

7. ORGANIZAÇÃO DAS TELAS
- A seção “Domínios cadastrados” foi removida de domains.php.
- domains.php ficou focado apenas no cadastro de domínios e reversas.
- dns-zones.php passou a ser a tela operacional de consulta das zonas forward.
- A listagem utiliza /var/cache/bind/master-aut/*.hosts.
- O sufixo .hosts não é exibido.
- A busca client-side foi preservada.
- O link “Editar Zona” aponta para edit-zone.php?zone=DOMINIO.
- O layout moderno da antiga listagem foi aplicado em dns-zones.php.

8. EXCLUSÃO SEGURA DE DOMÍNIOS
- Adicionado botão “Excluir” em dns-zones.php.
- A exclusão usa POST e proteção CSRF.
- É obrigatório digitar exatamente o nome do domínio no modal.
- O domínio e os caminhos são validados contra path traversal e caracteres perigosos.
- Os arquivos são confinados aos diretórios permitidos.
- A exclusão principal agora remove na mesma transação:
  - zona forward;
  - todas as reversas IPv4 associadas pelo SOA;
  - reversa IPv6 associada;
  - blocos correspondentes no named.conf.local.
- Isso evita a criação de novos resíduos ao excluir um domínio pelo painel.
- Antes da alteração são criados backups da configuração e dos arquivos envolvidos.
- Após a alteração é executado named-checkconf -z.
- Em caso de falha, os backups são restaurados.
- Após sucesso, o BIND é recarregado.
- As ações são registradas na auditoria com status, domínio, usuário, IP e informação de rollback.

9. REVERSAS ÓRFÃS
- Adicionada seção “Reversas IPv6 órfãs”.
- Adicionada seção “Reversas IPv4 órfãs”.
- Essas seções são destinadas a resíduos históricos ou importados de outros sistemas.
- Reversas IPv6 órfãs são detectadas por arquivos .rev6 sem forward correspondente.
- Reversas IPv4 órfãs são agrupadas pelo domínio identificado no registro SOA.
- As remoções usam modal, confirmação exata, POST, CSRF, backup, rollback e auditoria.
- Nenhum resíduo é removido automaticamente.

10. MENSAGENS
- Mensagens de sucesso foram ajustadas conforme o tipo de remoção.
- O toast de sucesso em dns-zones.php desaparece automaticamente após três segundos.
- Mensagens de erro permanecem visíveis.
- Caminhos internos não são exibidos na interface comum.

11. VALIDAÇÕES EXECUTADAS
- php -l domains.php
- php -l dns-zones.php
- named-checkconf -z
- Verificação dos links edit-zone.php?zone=DOMINIO.
- Verificação da correspondência entre arquivos e blocos no named.conf.local.
