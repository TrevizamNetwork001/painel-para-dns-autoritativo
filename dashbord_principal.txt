2. Saúde do servidor
3. Últimas atividades
4. Acesso rápido

============================================================
1. RESUMO DNS
============================================================

Criar primeira linha com 4 cards:

- Domínios Forward
- Zonas IPv4
- Zonas IPv6
- Registros DNS

Exemplo visual:

[🌐 Domínios Forward]  128
[🔄 Zonas IPv4]        32
[🧬 Zonas IPv6]        24
[📄 Registros DNS]     2457

Os números devem vir dos dados reais do painel.

Sugestões de origem:

Domínios Forward:
- contar arquivos de zona forward
- ou usar lógica já existente no dashboard atual

Zonas IPv4:
- contar zonas/arquivos *.rev

Zonas IPv6:
- contar zonas/arquivos *.rev6

Registros DNS:
- contar registros válidos nas zonas
- ignorar comentários, SOA, NS técnicos, linhas vazias e diretivas quando possível

Não precisa gráfico nessa etapa.

============================================================
2. SAÚDE DO SERVIDOR
============================================================

Criar bloco de saúde do servidor com:

- CPU
- RAM
- Disco
- Uptime

Exemplo:

CPU
18%

RAM
42%
3.2 GB / 7.7 GB

Disco /
35%
35 GB / 98 GB

Uptime
45 dias

Implementação sugerida:

CPU:
- Pode usar load average inicialmente
- /proc/loadavg
- ou top/vmstat se já houver função

RAM:
- Ler /proc/meminfo
- Calcular uso aproximado:
  MemTotal - MemAvailable

Disco:
- usar disk_total_space('/')
- usar disk_free_space('/')
- calcular percentual usado

Uptime:
- ler /proc/uptime
- converter segundos em dias/horas

Visual:
- usar barras horizontais simples com CSS puro
- cada barra com cor discreta:
  CPU azul
  RAM roxo
  Disco laranja
  Uptime verde/azul

============================================================
3. ÚLTIMAS ATIVIDADES
============================================================

Criar card "Últimas atividades".

Deve buscar os últimos eventos da tabela audit_logs.

Exibir os últimos 10 eventos.

Campos sugeridos:

- Hora/data curta
- Usuário
- Ação amigável
- Domínio ou registro
- Status

Exemplo:

18:07 admin adicionou PTR IPv6 em test-zone.example OK
18:05 admin adicionou AAAA www em test-zone.example OK
18:03 admin criou domínio test-zone.example OK
17:50 admin recarregou BIND OK

Ações devem ser amigáveis, não códigos crus.

Exemplos:

ADICIONAR_REGISTRO -> Adicionou registro
EDITAR_REGISTRO -> Editou registro
REMOVER_REGISTRO -> Removeu registro
ADICIONAR_PTR_IPV6 -> Adicionou PTR IPv6
EDITAR_PTR_IPV6 -> Editou PTR IPv6
REMOVER_PTR_IPV6 -> Removeu PTR IPv6
CRIAR_DOMINIO -> Criou domínio
REMOVER_DOMINIO -> Removeu domínio
RELOAD_BIND -> Recarregou BIND
RESTART_BIND -> Reiniciou BIND
LOGIN_SUCESSO -> Login realizado
LOGIN_FALHA -> Falha de login
LOGOUT -> Logout

Importante:
- Não mostrar SQL bruto
- Não mostrar nibbles reversos IPv6
- Não mostrar .rev6 se puder normalizar visualmente

Se o banco SQLite estiver indisponível:
- A dashboard não deve quebrar
- Mostrar mensagem:
  "Auditoria indisponível no momento"
