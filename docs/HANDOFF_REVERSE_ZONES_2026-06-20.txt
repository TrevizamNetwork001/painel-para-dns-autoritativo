5. LINKS DE EDIÇÃO

IPv4:
- Arquivos no formato A.B.C.rev são associados à zona:
  C.B.A.in-addr.arpa

Exemplos:
- 10.182.96.rev  -> 96.182.10.in-addr.arpa
- 198.50.0.rev   -> 0.50.198.in-addr.arpa
- 192.168.10.rev -> 10.168.192.in-addr.arpa

IPv6:
- O nome real da zona ip6.arpa é obtido do bloco zone cujo file aponta
  para o arquivo .rev6 correspondente.

Exemplo confirmado no servidor:
- gato.net.br.rev6 -> 7.b.d.0.2.0.0.2.ip6.arpa

O link utiliza:

edit-reverse-zone.php?zone=NOME_REAL_DA_ZONA_BIND

6. COMPATIBILIDADE DO EDITOR

edit-reverse-zone.php foi ajustado para aceitar o nome BIND recebido no
parâmetro zone.

O editor:
- procura o bloco correspondente no named.conf.local;
- valida que o arquivo pertence a /var/cache/bind/master-rev;
- converte internamente para o arquivo .rev ou .rev6;
- mantém os fluxos internos existentes de edição e remoção de PTR;
- mantém compatibilidade com links antigos que ainda enviem .rev/.rev6.

7. DETECÇÃO DE ARQUIVOS ÓRFÃOS

Um arquivo é considerado órfão somente quando não existe diretiva file
correspondente no named.conf.local.

A verificação considera:
- caminho completo configurado;
- caminho esperado em master-rev;
- basename do arquivo configurado.

Zonas configuradas recebem somente a ação "Editar Zona".
Arquivos órfãos recebem somente a ação "Remover órfão".

Também é reconhecido IPv6 legado armazenado com extensão .rev quando o
conteúdo possui $ORIGIN terminando em ip6.arpa.

9. REMOÇÃO SEGURA DE ÓRFÃOS

A remoção pelo painel exige:
- requisição POST;
- token CSRF válido;
- confirmação digitando exatamente o nome do arquivo;
- nome restrito aos formatos .rev e .rev6;
- basename idêntico ao valor recebido;
- realpath confinado a /var/cache/bind/master-rev;
- nova leitura do named.conf.local no momento da operação;
- confirmação de que o arquivo continua sem referência;
- backup temporário antes de unlink.

Se ocorrer falha depois da remoção, o painel tenta restaurar:
- conteúdo original;
- permissões originais.

A remoção de órfão:
- não altera named.conf.local;
- não executa named-checkconf;
- não recarrega o BIND;
- não remove automaticamente outros arquivos;
- não é executada apenas ao abrir a página.

10. AUDITORIA

As tentativas de remoção usam a ação:

REMOVER_ARQUIVO_REVERSO_ORFAO

São registrados:
- usuário;
- IP;
- domínio relacionado ou nome do arquivo;
- tipo da zona;
- caminho anterior;
- resultado SUCCESS ou ERROR;
- indicação de rollback.

A data e a hora são gravadas automaticamente no campo criado_em da tabela
audit_logs, usando CURRENT_TIMESTAMP.
