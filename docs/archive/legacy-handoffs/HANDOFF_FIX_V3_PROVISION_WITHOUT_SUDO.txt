Escopo: corrigir bootstrap/provisionamento para Debian limpo sem sudo.

1. BUG HOMOLOGADO

Servidor testado:
- Nome: NS03
- IP: 45.162.196.244
- Sistema: Debian 13.5
- Usuario SSH usado: conecta

Erro exibido antes da correcao:

[BOOTSTRAP]
debian_version=13.5

sh: 22: sudo: not found

Validacao manual no NS03:
- which sudo: sem saida
- dpkg -l sudo: nenhum pacote encontrado correspondente a sudo

Diagnostico:
O fluxo de provisionamento chamava sudo mesmo quando o servidor Debian limpo nao tinha o pacote sudo instalado. Isso quebra quando o login administrativo nao e root.

2. CORRECAO IMPLEMENTADA

Arquivo alterado:
- /var/www/html/painel/includes/dns_servers.php

O bootstrap remoto agora seleciona metodo de elevacao:

1. Se o usuario remoto ja for root:
   - ROOT_METHOD=direct
   - nao usa sudo
   - executa comandos diretamente

2. Se o usuario remoto nao for root e sudo existir:
   - ROOT_METHOD=sudo
   - usa sudo -n quando possivel
   - usa sudo -S com senha informada quando necessario

3. Se o usuario remoto nao for root, sudo nao existir, mas houver senha root/sudo informada:
   - tenta su - root -c 'true'
   - se autenticar, usa su - root -c para executar comandos privilegiados

4. Se o usuario remoto nao for root, sudo nao existir e nao houver senha root valida:
   - falha com mensagem amigavel:

ERRO: sudo não está instalado no servidor remoto. Use root ou forneça a senha root no campo sudo/root para continuar o provisionamento.

O mesmo padrao tambem foi aplicado ao fluxo de remocao/desativacao do agente remoto.

3. INTERFACE ATUALIZADA

Arquivo alterado:
- /var/www/html/painel/dns-servers.php

Texto adicionado na tela de adicionar servidor:

Para provisionar Debian limpo sem sudo, use login root ou informe a senha root no campo sudo/root. Usuário comum sem sudo não consegue provisionar servidor limpo.
